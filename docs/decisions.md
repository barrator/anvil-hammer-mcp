# Decisions

One line per decision: date, decision, reason. Newest at the bottom.

| Date | Decision | Reason |
|---|---|---|
| 2026-11-27 | Build from scratch, inspired by three existing MIT projects, credited in the README | Existing projects are local-only (stdio), and their design choices (public proxy by default, 170 tools, unguarded delete) do not match this project's principles |
| 2026-11-27 | Name: `anvil-hammer-mcp` | Distinct from the three existing `worldanvil-mcp` projects |
| 2026-11-27 | TypeScript | Most complete MCP ecosystem; prior art is JavaScript |
| 2026-11-27 | English only (code, comments, README, docs) | Widest audience for a public project; one version to maintain |
| 2026-11-27 | Whole API covered through a type registry and generic tools (about 14 tools), plus specialized tools for frequent tasks | Future use cases must not require new code; avoid the context cost and confusion of one tool per type and verb |
| 2026-11-27 | Writes are direct, with a change summary; dry run on request only | Usable from a phone; safety comes from backups, read-back, private drafts and conflict detection |
| 2026-11-27 | Hosted auth: built-in single-user OAuth server with a passphrase (DCR + Client ID Metadata Documents + PKCE) | Most reproducible for someone without the owner's infrastructure: needs only Docker, a domain and a passphrase; works with Claude's custom connectors out of the box. A static token in the URL was rejected (secret visible in logs and screenshots); custom auth headers need approval in Claude |
| 2026-11-27 | Conservative defaults: 60 writes/hour, backups 90 days, logs 180 days, responses about 25,000 characters | Safety first; all configurable |
| 2026-11-27 | Egress limited to World Anvil through an egress proxy in docker-compose, from the first hosted release | Reproducible anywhere without touching the host firewall; World Anvil's IPs change (Cloudflare) so filter by domain |
| 2026-11-27 | Work split into stages A–F, each with its own brief, plan approval before code | Keeps each step reviewable; the owner reviews plans and PRs as a counterweight |
| 2026-11-27 | A registry field is `verified` only when the live-test harness has observed it in a real response; spec and notes entries start `unverified` | Notes can be wrong or outdated; only a real response is evidence |
| 2026-11-27 | An element's world is resolved from its own `world` field, else through its parent chain; reads are refused only when no chain is found | The `world` field is missing at some granularities; refusing too eagerly would block legitimate reads, guessing would leak |
| 2026-11-27 | `blocked` worlds answer exactly like missing elements | An attacker-controlled prompt must not learn that a blocked element exists |
| 2026-11-27 | World access is checked before any list call to World Anvil | Nothing about a blocked world should even be fetched when it can be avoided |
| 2026-11-27 | Remembered `updateDate`s (and resolved worlds) are stored per MCP session | HTTP mode serves several clients; one client's reads must not authorize another's writes |
| 2026-11-27 | Truncation notices suggest `fields` for `wa_get` and `offset` for lists | Each points to the parameter that actually helps |
| 2026-11-27 | Access file variable: `WA_ACCESS_FILE`; size limit variable: `WA_MAX_RESPONSE_CHARS` | Consistent `WA_` prefix |
| 2026-11-27 | Runtime dependencies: MCP SDK and zod only (zod is required by the SDK for tool schemas) | Minimal dependencies |
| 2026-11-27 | Live tests read keys from files only; the report holds structure only (field names, counts, pass/fail) | Runs on the owner's VPS where keys are files; the report must be pasteable in a public PR |
| 2026-11-27 | Node.js 22 or newer | Current LTS line |
| 2026-11-27 | Stage A live run: observed fields promoted to `verified` through `src/registry/observed.ts` only; subscriber groups, timelines and history stay `unverified` until stage B creates test instances | Only real responses count as evidence; one place to audit what was observed |
| 2026-11-27 | The `success` flag is stripped from compact output and from the registry comparison | It is a response flag, not an element field |
| 2026-11-27 | `WA_MAX_RESPONSE_CHARS` accepted by the owner | The architecture already makes the max size configurable |
| 2026-11-27 | The cloud development environment may reach worldanvil.com to read the public spec, but never holds keys; live tests run only on the owner's VPS | Keys stay on infrastructure the owner controls |
| 2026-11-27 | No AI attribution in commits or PRs (no co-author trailer, session link or footer); the owner is author and committer; AI assistance disclosed once in the README | The maintainer answers for every change; per-commit AI co-authorship is contested in open source, while a single disclosure stays honest |
| 2026-11-28 | Template probe (read-only live run) before writes; the 4 probed templates (person, organization, settlement, rank) refuse unknown fields, unprobed templates accept them with a warning | Strict refusal needs a real field list; the read-back still reports what World Anvil ignored |
| 2026-11-28 | Field kinds of probed templates are inferred from names and the spec and marked `kindConfirmed: false` unless a real value was seen | A field name being real does not prove what it holds |
| 2026-11-28 | Generic `wa_create`/`wa_update` warn on unknown fields instead of refusing | The registry is incomplete; read-back catches ignored fields |
| 2026-11-28 | References to another world are refused; an element cannot change world; worlds are never created or deleted | Writes stay inside one checked world |
| 2026-11-28 | Image and other unregistered references are refused for now | Their world cannot be checked until the type is registered |
| 2026-11-28 | Restoring a deleted element lists its own links; `scan_links: true` scans up to 100 world articles for the old ID | A full scan is too slow to do by default |
| 2026-11-28 | Backups default to the user's data folder (`XDG_DATA_HOME`, else `~/.local/share`), never the current directory | Predictable location outside the project; `WA_BACKUP_DIR` overrides |
| 2026-11-28 | A failed backup refuses the write | Principle 4: no modification without a safety net |
| 2026-11-28 | Delete also requires a prior read and an unchanged `updateDate` | Deleting is the most destructive write |
| 2026-11-28 | Live write test deletes what it created, with delete enabled only for that test; `test:live:cleanup` empties the ledger after an interrupted run | Leave the test world clean; recover from crashes |
| 2026-11-28 | Harness write mode: a create must prove it targets the test world (`world.id` or a known parent); created elements are recorded in the ledger automatically | A create without world could otherwise land in another world |
| 2026-11-28 | Commit signing disabled for this repository | The environment's signing key is unknown to GitHub, which shows "Unverified": worse than unsigned |
| 2026-11-28 | A failed live check fails the run, including checks made in `afterAll`; check details mask IDs and UUIDs | A green run must mean every check passed; details must stay pasteable in a public PR |
| 2026-11-28 | For elements without `updateDate`, conflict detection compares the content seen at the last read; `expected_update_date` is refused for them | Keeps the "never overwrite someone else's work" rule when the date is missing |
| 2026-11-28 | Registry: no `isDraft` for timelines, history events and categories; neither `state` nor `isDraft` for subscriber groups; create defaults follow | Observed in the stage B write run: those fields come back null |
| 2026-11-28 | Restore never sends placeholder references (`{"id": -1}`) or image references | They are certainly ignored (placeholder) or cannot be checked (images); they must not show up as ignored fields |
| 2026-11-28 | A public backup is restored as private unless `restore_public: true` is passed (replaces the earlier "recreated public with a warning") | Owner decision: nothing becomes public without an explicit request |
| 2026-11-28 | Second stage B write run: observed fields of subscriber groups, timelines and history events promoted to `verified`; history fields needed by `wa_upsert_timeline_event` (finer dating, article links) added now, the other unregistered timeline/history fields deferred to stage E | Only what a coming tool needs is added before stage E; the rest is listed in `docs/stage-e.md` |
| 2026-11-28 | Empty-but-never-stored keys (`isDraft` on timeline/history/category; `state`/`isDraft`/`isWip` on subscriber groups) stay out of the registry, guarded by a test | They look like fields in responses but writing them does nothing |
| 2026-11-28 | Own BBCode ⇄ Markdown converter, no code reused from wlcarden (one-way, regex-based, no round trip) and no new dependency | A byte-identical round trip needs a converter designed for it; no Markdown library offers it |
| 2026-11-28 | Round trip guaranteed by construction: each converted block is checked on the spot, falls back to a `⟦…⟧` placeholder, then plain mode, then the whole field raw | The guarantee must not depend on the converter knowing every form |
| 2026-11-28 | Paragraph mode follows the editor: `[p]` per paragraph, `[br]` for line breaks, single `\n` between blocks; new Markdown is written in that form; fields in another layout keep it (plain mode) | Writes must look like the editor's own text |
| 2026-11-28 | Empty paragraphs and unknown or non-canonical forms (tags with parameters, uppercase, heading ids for now) shown as `⟦…⟧`; minimal escaping only where the converter would interpret a character | Readable French text; exact bytes |
| 2026-11-28 | `append` separator: the editor's block separator (`\n`) in paragraph fields, a blank line in plain fields, none when the field already ends with a newline | One new paragraph, in the field's own layout |
| 2026-11-28 | Replacing a non-empty text field needs `replace_fields` (list) in `wa_update` and `wa_update_article`; restore is exempt | Confirmation is per field, explicit |
| 2026-11-28 | Only mentions new to a field are checked against the world, with the per-session resolver cache | Existing mentions were already there; each target is read once |
| 2026-11-28 | A field's layout (mode plus leading/trailing blank characters) is taken from its current text on write | Fields end with a newline in the editor's form; keeping it keeps the field in paragraph mode and byte-identical |
| 2026-11-28 | The editor's lists `[ul]\n- …\n-- …\n[/ul]` ⇄ two-level Markdown lists; headings with an id ⇄ `# Title {#id}` | Most frequent remaining placeholders in real worlds; readability without losing a byte |
| 2026-11-28 | Sidebar lines are only the exact `--Key::Value--`; `-` is escaped only at a line start where it would make a list | List sub-items look like sidebar lines; French dialogue dashes must stay readable |
| 2026-11-28 | `history` treated as a text field for every article template (`textFieldNames`), without making it valid for probed templates | Seen with BBCode in unprobed templates; conversion must not loosen strict template validation |
| 2026-11-28 | The BBCode probe reports, per plain-mode field, the rule that blocked paragraph mode, and the kinds of remaining placeholders | Readability work must be driven by real data, still without content |
| 2026-11-28 | `history` is a generic article field (BBCode), marked in the registry and verified from the probe; the separate `textFieldNames` mechanism is removed | One source of truth for the probe and the converter |
| 2026-11-28 | An empty line inside a paragraph is written as a line holding only `\` (like a Markdown hard break) | Converts `[br]` at a paragraph's ends and doubled `[br]` instead of keeping them as placeholders |
| 2026-11-28 | The converter names the rule behind every placeholder and plain-mode fallback; the probe reports them with known WA tag names only | Remaining readability gaps are found from real data without exposing content |
| 2026-11-28 | Fallback per block, never per field: a block that does not convert is one placeholder on its own line; plain mode only when no block reads as text | One odd block must not make a whole field unreadable |
| 2026-11-28 | A run of empty paragraphs is one placeholder `⟦[p][/p]×N⟧`; `×` is escaped inside ordinary placeholders so the compact form is unambiguous | The editor leaves hundreds of empty paragraphs at the end of fields |
| 2026-11-28 | `[s]` ⇄ `~~`, `[hr]` ⇄ `---`, one-line `[quote]` ⇄ `> `, headings h1–h6 with id, `[ul]`/`[ol]` on three levels (`[ol]` numbered in Markdown, written back as the editor's `- ` lines) | Forms the editor's buttons produce |
| 2026-11-28 | `[category:]`, `[timeline:]`, `[secret:]` links in text are references: new ones must be in the same world; new `[img:]` refused | Same rule as every other reference (stage B) |
| 2026-11-28 | A sidebar line may end with spaces or tabs (kept byte for byte); no other variant of `--Key::Value--` counts | The real form in family sidebars; the editor leaves the space |
| 2026-11-28 | Mention syntax confirmed live: `@[Title](Article:<uuid>)` for articles; `[category:]`/`[timeline:]` tags for other elements | The content test rendered an API-written mention as a link |
| 2026-11-28 | Owner accepted: `[secret:]` links checked against the world, new `[img:]` refused while the image type is not registered, a whitespace-only paragraph `[p] [/p]` kept as a placeholder | Same reference rule everywhere; an invisible paragraph must stay visible |
| 2026-11-28 | Hosted auth: Client ID Metadata Documents as the main mechanism, pre-registered public clients for other clients, no Dynamic Client Registration (replaces DCR + CIMD from 2026-11-27) | The 2026-07-28 MCP spec says authorization servers SHOULD support CIMD and deprecates DCR; CIMD is Claude's recommended option ("Use Claude's published identity") and needs no configuration; pre-registration is meant for an existing relationship. Cost accepted: a second network exit, to claude.ai, limited by the gateway |
| 2026-11-28 | CIMD documents accepted only from `WA_OAUTH_CIMD_HOSTS` (default claude.ai): https, no redirect, 5 s, 5 KB, JSON, `client_id` equal to the URL, `token_endpoint_auth_method` "none", bounded cache that follows HTTP headers | Fetching a URL chosen by the request is a server-side request forgery risk; the gateway allows the same host |
| 2026-11-28 | The passphrase file holds a scrypt hash made by `hash-passphrase`, never the passphrase; at least 12 characters; 5 failures per address per 15 min, 20 per hour in total | The passphrase never sits on the server's disk; the global limit holds when an attacker changes addresses |
| 2026-11-28 | Gateway: nginx, HTTP relay for ingress and TLS passthrough chosen by SNI for egress (www.worldanvil.com and claude.ai, port 443); Squid with `HTTPS_PROXY` rejected | A container on an internal network alone cannot publish a port (observed), so a relay is needed anyway; the application keeps no proxy setting, the API base URL stays a constant, and TLS stays end to end |
| 2026-11-28 | `X-Forwarded-For` trusted by the server only from the gateway, and by the gateway only from the host side of its network (the reverse proxy) | Attempt limits and the log need the real client address; a forged header from anywhere else is replaced |
| 2026-11-28 | Tokens are opaque, stored as SHA-256 hashes only; access 30 min in memory; refresh rotated at each use, 30 days idle, 90 days max, reuse revokes the grant (60 s grace) | Short-lived access (spec SHOULD), rotation for public clients (spec MUST, Claude requirement); a lost response must not lock the owner out |
| 2026-11-28 | Added at the owner's request: `/revoke`, `check`, `revoke-all` | Revoke one grant, test the keys from the VPS, cut every sign-in at once |
| 2026-11-28 | Image for linux/amd64 only, distroless Node.js runtime, non-root (65532) | The owner's VPS is x86_64; no shell or package manager in the runtime |
| 2026-11-28 | Node.js 26 (active LTS) for the image and the main CI job; `engines` >=24; CI on 24 and 26; TypeScript 6.0.3 | Current LTS lines; typescript-eslint does not support TypeScript 7 yet (peer <6.1.0) |
| 2026-11-28 | Runtime dependencies: MCP SDK, zod and express (express is the SDK's own HTTP framework, already installed with it, same version) | The SDK's auth handlers and middleware are Express-based; importing it directly must not rely on a transitive dependency |
| 2026-11-28 | Protocol stays the SDK's (2025-11-25, the version Claude documents); 2026-07-28 authorization rules that apply are followed (`iss`, no `offline_access` in PRM or `WWW-Authenticate`) | Compatible with Claude today and with the current spec |
| 2026-11-28 | One version source: package.json (server version, User-Agent); a release tag must match it; first hosted release 0.2.0 | No version drift between the image, the npm package and the API User-Agent |
| 2026-11-28 | Data folders are bind mounts under `deploy/data/` owned by 65532; administration commands run with `docker compose exec` | Easy to edit `access.json` and to back up from the host; `docker compose run` clashes with the server's fixed address |
| 2026-11-28 | The secret file check (no permission for other users) also applies to `*_FILE` in stdio mode, live tests included | One rule for every key file |
| 2026-11-28 | Dependabot ignores TypeScript 7 and later; remove the ignore entry once typescript-eslint accepts TypeScript 7 | typescript-eslint's peer range is `typescript <6.1.0`; Dependabot PR #6 failed at `npm ci` for that reason and was closed |
| 2026-11-28 | Hosted deployment verified on a real VPS: v0.2.0 behind Caddy with an sslip.io name; `egress-check` 7/7 with nginx 1.30.6 and again with 1.31.7 (PR #5 merged); `check` reports World Anvil ok; Claude connected with its published identity (CIMD): authorization, passphrase, token, tools usable | The checks the development sandbox could not run (reaching World Anvil and claude.ai) passed on the target infrastructure |
